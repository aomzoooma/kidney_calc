# Optional local food-name translation

USDA recipe search can optionally translate one food query or one selected USDA description at a time with the approved `scb10x/typhoon-translate-4b` Ollama model. `OLLAMA_TRANSLATION_MODEL` can pin that model name with or without `:latest`; other model names are rejected until reviewed. The API always connects to `127.0.0.1:11434`; it does not accept a remote Ollama URL, and the app does not download models.

The USDA query box sends only its food text and requested language to the app's loopback Ollama endpoint. It does not include recipe, profile, patient, or nutrition data. Use only a trusted local Ollama configuration; the app cannot prove where a daemon sends or runs model work. Do not put patient names or other personal data in the query box. After the caregiver explicitly accepts an English translation, the app sends that term to USDA FoodData Central for the requested search.

For a Thai query, the translated English text appears as a suggestion. The caregiver must press **Search USDA with this translation** before USDA receives it. A translated result appears below the original USDA description and state, as a reading aid only. It does not change the USDA ID, food state, nutrients, or selection. Review the original USDA name and preparation state before adding it. Translation does not bypass the synthetic-only calculation gate.

If Ollama or the configured model is unavailable, translation fails with a short message; the existing dictionary suggestions and direct English search remain available. Requests have a 30-second timeout, accept at most 300 characters, cap model output, and run one at a time. No prompts or model responses are written to application logs.

## Model and terms

The [official Ollama library](https://ollama.com/scb10x/typhoon-translate-4b) lists `scb10x/typhoon-translate-4b` as a 4B Thai-English translation model; its Q4_K_M download is about 2.5 GB. The [upstream model card](https://huggingface.co/typhoon-ai/typhoon-translate-4b) identifies the Gemma license and says model users must also agree to the [OpenTyphoon Terms and Conditions](https://opentyphoon.ai/tac) and [Privacy Notice](https://opentyphoon.ai/privacy). The model uses the [Gemma Terms of Use](https://ai.google.dev/gemma/terms/). Read those current terms before installing or using the model. In particular, the OpenTyphoon terms prohibit personal data in model input. The project does not bundle or redistribute model weights.

Ollama setup and model installation are separate from this application. After reviewing the terms and installing Ollama/model, start the Ollama service before using the translation buttons. The API asks `/api/tags` whether Ollama reports the approved model name, a nonzero size, and Gemma 3 family. This metadata comes from the daemon; it is not a cryptographic signature or proof that the daemon cannot route work elsewhere. The app itself sends requests only to loopback with environment proxies disabled. That limits this app's network path; offline execution still depends on a trusted, unmodified local Ollama service and model. This environment had no Ollama executable or model installed, so runtime inference was not verified. Never configure a remote endpoint or forward this request to a hosted model service.
